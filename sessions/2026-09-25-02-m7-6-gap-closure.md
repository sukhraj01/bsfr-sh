## Findings

- **The real finding is H2 (resample strategy), not H1/H3/H4.** Oversampling — bootstrap-
  duplicating the 41,413 real ransomware rows to 180,000 (~4.35x average duplication) and
  undersampling benign to 20,000 — scores 0.9690-0.9723 under a random split but only 0.8746-0.9363
  under a grouped split: a 5-10 point swing, several times larger than Q10's largest leakage
  signature (+0.92pt for decision tree). The mechanism is direct and mundane: a duplicated row
  carries its original's address, so a non-grouped split routinely puts a literal copy of a
  training row into the test set. This is a genuinely different leakage mechanism from Q10's two
  candidates (`address`-as-feature, non-grouped split on the *original*, non-duplicated data),
  large enough to matter on its own.
- **Dead end (expected, still worth recording): H1's four labelled cells collapse to two.**
  scikit-learn's `DecisionTreeClassifier` defaults are already `max_depth=None,
  min_samples_split=2, min_samples_leaf=1` — "fully grown" by default — so the task's
  "default" and "explicit fully grown" cells for a given criterion are bit-identical estimators.
  Verified with an in-script assertion rather than left as an assumption. Only two genuinely
  distinct configurations exist here (gini, entropy); the 8-cell table records this rather than
  silently deduplicating it.
- **Dead end: H4's `year_dropped` moves the wrong direction for a leakage story.** If `year`
  encoded temporal information that let a model "cheat" (e.g., knowing which ransomware families
  were active in which year), dropping it should *help* honest generalisation or at least not
  hurt it much. It costs ~3 accuracy points instead — `year` is a genuinely useful feature, not a
  leak. This closes a plausible-sounding hypothesis the report had not previously tested.
- **H3 closes cleanly and quickly.** 20 seeds on both the production protocol and Q10's best cell
  show small variance (std 0.0050 and 0.0011 respectively); 5-fold group-CV agrees with the
  single-split numbers. No surprises, no dead ends — this hypothesis was the fastest to rule out
  (four models x 20 seeds plus a 5-fold CV, all in well under a minute of the ~5-minute total run).
  Recorded anyway per CLAUDE.md's "an unrecorded dead end gets retried."
- **Incidental finding, not pursued:** logistic regression's 20-seed accuracy std is 0.1743 (vs.
  ~0.005 for the tree-based models) because it occasionally converges to predicting all-benign,
  scoring exactly 0.10 — the constant-negative floor at this class balance. Not investigated
  further since LR is not the paper's best-reported algorithm and this doesn't bear on the gap.
- **The stacked worst case (H5) is dominated by one ingredient.** H5's 0.9747 is barely above
  H2's best single cell (oversample x decision_tree x random, 0.9723) — the other four stacked
  choices (entropy criterion, `year x day` interaction, address kept, random split on top of
  what's already a random-split resample) contribute only ~0.2-0.3pt combined. This is useful:
  it means the report's conclusion can name a *specific* leading candidate (resample strategy)
  rather than a vague "some combination of everything."
